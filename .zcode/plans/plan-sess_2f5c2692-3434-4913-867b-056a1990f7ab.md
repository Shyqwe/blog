# 静态博客改造为动态博客

## Context（背景）

现有博客是纯静态三件套（`index.html` / `about.html` / `css/style.css`），发文章要手动改首页 HTML。目标：保留"前端三件套 + 原生 JS"的技术风格，在 Vercel **Other** 框架下利用其原生支持的 `api/` Serverless Functions + 数据库，实现你选的全部功能：在线发布文章（管理后台）、评论、搜索/标签/归档、浏览量/点赞。不引入任何框架。

## 架构

- **静态页面照旧**：首页/归档/关于/管理页仍是手写 HTML + CSS + 原生 JS，数据通过 `fetch('/api/...')` 获取
- **文章阅读页由 Node 服务端渲染**：`/posts/:slug` 通过 vercel.json rewrite 指向 `api/render/[slug].js` 返回完整 HTML。原因：动态 slug 无法用静态文件承载干净 URL；服务端渲染对 SEO 友好；markdown 转 HTML 需要在一端完成
- **数据库**：Vercel Postgres（面板一键开通、免费档、连接串自动注入 `POSTGRES_URL`），驱动用 `postgres`（postgres.js），兼容任何 Postgres
- **认证**：单管理员。`ADMIN_PASSWORD` 环境变量 + HMAC 签名 httpOnly cookie（node:crypto，7 天有效期），不加依赖
- **依赖**（root package.json）：`postgres`、`marked`（markdown→HTML）、`sanitize-html`（防 XSS）

## 数据库

首次请求时 `ensureSchema()` 自动 `CREATE TABLE IF NOT EXISTS`，无需手动迁移：

- `posts`：id, slug(唯一), title, content(markdown), tags text[], published bool, views int, likes int, created_at, updated_at
- `comments`：id, post_slug, name, body, created_at

## API（api/ 目录，`_` 开头的文件不会被路由）

| 文件 | 方法 | 说明 |
|---|---|---|
| `api/_db.js` | — | 连接 + ensureSchema |
| `api/_auth.js` | — | 签发/校验管理员 cookie |
| `api/auth.js` | POST/DELETE | 登录 / 退出 |
| `api/posts.js` | GET/POST | 列表（`?q=` 搜索、`?tag=` 过滤、`?all=1` 管理员含草稿）/ 新建 |
| `api/posts/[slug].js` | GET/PUT/DELETE | 详情 JSON / 编辑 / 删除（管理员） |
| `api/render/[slug].js` | GET | 服务端渲染阅读页（公开），顺带 views+1 |
| `api/meta.js` | GET | 标签统计 + 按月归档统计 |
| `api/comments.js` | GET/POST | 评论读取 / 发表（蜜罐字段防垃圾） |
| `api/likes.js` | POST | 点赞 +1（前端 localStorage 防连点，个人博客可接受的简化） |

## 前端页面（沿用现有 CSS 变量与设计语言）

- `index.html` — JS 动态渲染列表 + 搜索框 + 标签筛选（`js/index.js`）
- `archive.html`（新）— 按月归档 + 标签云（`js/archive.js`）
- `admin.html`（新）— 登录 → 文章管理列表（编辑/删除/发布开关）→ markdown 编辑器（标题/slug/标签/正文），纯表单（`js/admin.js`）
- 阅读页（api/render 生成）— 正文 + 浏览量 + 点赞 + 评论区（`js/post.js` 负责交互）
- `about.html` — 导航加"归档"
- `css/style.css` — 扩展表单/按钮/评论/标签样式

## 配置

- `vercel.json`：加 rewrite `/posts/:slug → /api/render/:slug`，cleanUrls 与安全头保留
- `.gitignore`（新）：`.env`、`node_modules`
- 部署时：Vercel 项目 Storage → Create Vercel Postgres；环境变量加 `ADMIN_PASSWORD`

## 验证

1. `npm install`；本地建 `.env`（`POSTGRES_URL` + `ADMIN_PASSWORD`）
2. `npx vercel dev` 启动本地环境
3. 浏览器走通全流程：`/admin` 登录 → 新建文章 → 首页/搜索/标签/归档可见 → `/posts/slug` 阅读页 → 发评论 → 点赞 → 未登录调管理 API 应 401
4. 推送 GitHub → Vercel 导入（Framework: Other）→ 开 Postgres、设 `ADMIN_PASSWORD` → 线上复验
